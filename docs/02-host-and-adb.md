# Подготовка компьютера и ADB

Все команды PowerShell выполняются из корня клонированного репозитория. Сначала подключите один целевой модем напрямую к исправному USB-порту. Для первого запуска установленных APK root не нужен; для политики сети и системного автозапуска потребуется временный root именно на проверенной прошивке.

## Инструменты

Скачайте [Android SDK Platform Tools с сайта Google](https://developer.android.com/tools/releases/platform-tools), распакуйте весь архив, включая DLL рядом с `adb.exe`. Установленные Android Studio или Platform Tools также подходят. Для установки готовых файлов Java, Python, Gradle и Android Studio не требуются.

В диспетчере устройств Windows должны работать Android ADB Interface и сетевой адаптер Remote NDIS. На проверенном модеме это USB `VID_05C6&PID_90B4`, ADB `MI_03`, RNDIS `MI_00`. Дополнительный интерфейс `MI_02` не использовался; ошибку его драйвера не нужно исправлять заменой всех драйверов устройства. Используйте драйвер, соответствующий конкретному интерфейсу и вашей ОС.

```powershell
$adb = 'C:\tools\platform-tools\adb.exe' # укажите свой путь
& $adb devices -l
$serial = '86e3aa1e' # замените на serial целевого USB-устройства
& $adb -s $serial shell getprop ro.build.fingerprint
& $adb -s $serial shell getprop ro.build.version.release
& $adb -s $serial shell id
```

Нормальное состояние — `device` и `uid=2000(shell)`. При `unauthorized`, `offline` или отсутствии устройства сначала решите проблему подключения. `adb connect 192.168.100.1` для этого проекта не требуется. Все команды используют `-s`, чтобы не затронуть другой телефон или модем.

Сверьте fingerprint с [паспортом устройства](01-hardware.md). Скрипты откажутся менять другую сборку. Простое снятие этой проверки не обеспечивает совместимость: нужны повторная проверка пакетов, USB-интерфейсов, init и механизмов перезагрузки другой прошивки.

## Временный root на этой прошивке

Обычная команда `adb root` здесь возвращала ошибку пароля производителя. Проверенный способ приведён ниже; скрипты установки и резервного копирования выполняют его и обратный переход сами.

```powershell
Import-Module .\scripts\Modem.psm1 -Force
Assert-Modem $adb $serial
Set-ModemRoot $adb $serial $true
Invoke-ModemShell $adb $serial 'id'
# ... только необходимые административные команды ...
Set-ModemRoot $adb $serial $false
Invoke-ModemShell $adb $serial 'id'
```

Внутри используются `setprop service.adb.root 1` и `busybox killall adbd`, затем ожидание переподключения. При завершении — свойство `0` и повторный запуск adbd. Прерывается только ADB на модеме. После возврата ожидается `uid=2000`, а не `uid=0`.

У старого Android код возврата процесса `adb shell` может быть нулём даже при ошибке удалённой команды. `Invoke-ModemShell` проверяет отдельный маркер с удалённым кодом завершения. Поэтому результат установки также проверяется по маркеру и фактическому состоянию, а не только по `$LASTEXITCODE` компьютера.

Если политика PowerShell блокирует локальный сценарий, можно запустить его в отдельном процессе с `powershell -NoProfile -ExecutionPolicy Bypass -File ...` после ознакомления с файлом. Менять общесистемную политику выполнения не требуется.
