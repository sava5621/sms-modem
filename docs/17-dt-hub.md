# DT — полный сервис 1.8

Профиль для UFI103S_V01 с fingerprint
`qcom/msm8916_32_512/msm8916_32_512:4.4.4/KTU84P/eng.rel.20221021:userdebug/test-keys`.
Это обновление первого DT с приложения `local.modem.sms` 4.1 на `local.modem.hub` 1.8-DT.
Профили UF7 и UFI 2025 не изменены.

## Доступ и возможности

- DT: `http://192.168.101.1:8088/` (полный статус), также порт 8000.
- Для записи приветствия с микрофона: `http://localhost:18081/`.
- UF7 остаётся на `192.168.100.1` и `localhost:18080`; устройства работают одновременно.
- Те же вкладки «Отправители», «СМС», «Звонки», смешанная история, поиск, фильтры, четыре счётчика, сигнал, номер из SIM, Gauge памяти и WebSocket.
- Пароля и настройки LED в интерфейсе нет. Очистка архива с подтверждением удаляет СМС, звонки и аудио, сохраняя приветствие; во время звонка очистка блокируется.
- Автоответ: 5 секунд ожидания → приветствие → 20 секунд записи → сброс. Приветствие можно записать, загрузить и прослушать в интерфейсе.
- Записи звонков воспроизводятся через WAV-кеш, исходные 3GP остаются доступны для скачивания.

Номер отображается только если записан на SIM и доступен через `getLine1Number`; для установленной MegaFon он пуст.
Код не делает платных исходящих звонков, СМС или USSD для определения номера.
Женское приветствие перенесено на экземпляр владельца отдельно от APK. Личные аудиозаписи в Git не входят.
Порт 80 на этой прошивке не перенаправляется; используйте явно 8088 или локальную панель.

## Сохранённая сеть

DT зарегистрирован с **`mobile_data=0`**. Значение оставлено выключенным; обход UF7 с `mobile_data=1` сюда не переносится.
Не меняются IMEI, NV, диапазоны, радиорежим или прошивка.
Wi-Fi/AP/сканирование, roaming, tethering и forwarding выключены, watchdog без сигнала отключён.
`persist.adb.tcp.port=-1`, `service.adb.tcp.port=-1`; USB ADB возвращён к UID 2000.
Приложение проверяет фактический слушающий сетевой ADB и при необходимости перезапускает только adbd.

На DT уже были root-скрипты USB LAN и SMS-only. Два файла `/system/etc/modem-usb-lan.sh`
и `/system/etc/sms-only-policy.sh` адаптированы под 192.168.101.0/24 и TCP 80/8000/8088.
Существующий вызов из `init.qcom.post_boot.sh` сохранён. `/system` снова смонтирован только для чтения.
Правила SMS_ONLY разрешают USB-подсеть и loopback, блокируют другой IP-трафик и пересылку.
Дополнительно netd разрешает только loopback/USB; приложение поддерживает настройки каждые 5 секунд.

## Первичный перенос с 4.1

Требуются явно разрешённый временный root, совместимая platform-подпись и уже настроенный DT 4.1 с root USB/SMS-only helper.
Это не универсальный установщик на заводской модем. Точный fingerprint и контрольные суммы проверяются.

```powershell
.\scripts\Migrate-Dt.ps1 -Serial '<USB serial DT>' -Adb '<adb.exe>' -AllowTemporaryRoot
# Только адаптер с соответствующим USB parent, запуск от администратора:
.\devices\dt-20221021\host\configure-windows.ps1 -Serial '<USB serial DT>'
```

Перед изменениями сохраняются старый APK, данные `local.modem.sms`, согласованная SQLite-копия,
исходные системные скрипты, правила firewall и настройки. Закрытая копия остаётся на устройстве и в `.local/dt/`.
`migrate.sh` отказывается перезаписывать существующую базу нового приложения. Старый пакет сохраняется отключённым.
Переносится вся база v2, включая отметки удаления; сервис обновляет её до v3 с поиском и отметками прочтения.
Старый архив не имел отметок прочтения, поэтому перенесённые сообщения сначала считаются непрочитанными.

При частичной ошибке сценарий возвращает обычный ADB через `finally`. Не запускайте миграцию повторно поверх созданной базы:
сначала проверьте закрытую резервную копию и фактический этап остановки. Возврат старого сервиса требует остановить/отключить
новый Hub, вернуть прежние root-скрипты и адрес Windows; нельзя запускать оба обработчика на одном устройстве.
После переключения новые СМС сохраняются уже в Hub, поэтому полный откат старой копии потеряет новые события.
`RestoreActivity` возвращает настройки приложения, но не заменяет резервные копии системных скриптов.

## Обновление и сборка

```powershell
.\scripts\Install-Dt.ps1 -Serial '<USB serial DT>' -Adb '<adb.exe>'
.\scripts\Verify-Dt.ps1 -Serial '<USB serial DT>' -Adb '<adb.exe>' -OutputFile '.local/dt/verification.json'
.\scripts\Build-Dt.ps1 -AndroidJar '<API19 android.jar>' -BuildToolsDirectory '<build-tools>' `
 -EcjJar '<ecj.jar>' -PlatformKey '<вне Git>\platform.pk8' `
 -PlatformCertificate '<вне Git>\platform.x509.pem' -Java '<java.exe>'
```

Обновление существующего Hub выполняется через `install -r`, без удаления приложения или очистки данных.
APK `artifacts/sms-modem-dt-1.8.apk` подписан совместимым с заводским образом публичным AOSP platform test-сертификатом.
Ключи не входят в репозиторий. Сборка использует новый каталог `build/dt/<id>`.

## Локальная панель Windows

```powershell
.\devices\dt-20221021\host\start-local-panel.ps1 -Node '<node.exe>'
.\devices\dt-20221021\host\install-local-panel-startup.ps1 -Node '<node.exe>'
```

Отдельный скрытый Node-процесс слушает только 127.0.0.1:18081 и передаёт HTTP/WebSocket на DT:8000.
Ярлык «DT Local Panel» запускается при входе пользователя; ярлык и процесс UF7 остаются отдельными.
Остановка: `host/stop-local-panel.ps1 -RemoveStartup`. При этом сервис модема продолжает работать.
Автозапуск после полной перезагрузки Windows пока не проверен: владелец отложил её.
