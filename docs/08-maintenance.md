# Обслуживание и восстановление

## Обычная эксплуатация

Оставьте модем с SIM в сервере, USB-сети задайте статический локальный адрес, а браузер открывайте по необходимости. SMS-служба работает без браузера. Регулярность закрытых резервных копий выберите по ценности архива; их создание описано в [этапе 3](03-backup.md).

После переноса на другой сервер проверьте его драйвер RNDIS, адрес, отсутствие шлюза/DNS и поведение питания USB. Настройки `/system` и приложений находятся на модеме, адрес USB-адаптера — на каждом компьютере отдельно.

`/data/local/sms-only/health.log` и `control.log` ротируются при превышении примерно 64 КиБ, для каждого остаётся предыдущий файл. Это несколько ограниченных файлов, а не бесконечный журнал. Журналы содержат состояние устройства, а не сообщения. Не запускайте постоянный `logcat` с выводом всех буферов в публичный каталог.

## Обновление APK

Сначала сделайте резервную копию. Обновляйте пакет с тем же именем и той же подписью через `adb install -r`; после этого проверьте HTTP и сохранность архива. Исходный закрытый `signing.jks` хранится у владельца отдельно от Git. Наличие исходников и готового APK не позволяет восстановить закрытый ключ.

`pm clear local.modem.sms` и `adb uninstall local.modem.sms` удаляют данные приложения. Они не являются способом перезапуска. Для обычного перезапуска достаточно `am force-stop local.modem.sms`, затем `am start -n local.modem.sms/.MainActivity`; за время паузы системный inbox остаётся источником повторного импорта.

## Восстановление архива СМС

Восстанавливайте собственный проверенный tar из [Backup-Sms.ps1](../scripts/Backup-Sms.ps1) на совместимую версию `local.modem.sms`. Сначала установите подписанный APK, сохраните текущие данные отдельно и проверьте список архива. Следующие действия выполняются вручную в root ADB shell; строки с метками заменяются реальными значениями:

```powershell
Import-Module .\scripts\Modem.psm1 -Force
Set-ModemRoot $adb $serial $true
& $adb -s $serial push .\.local\backups\<каталог>\sms-app-<метка>.tar /data/local/tmp/sms-restore.tar
& $adb -s $serial shell
```

В открытом Android shell:

```sh
busybox id -u
dumpsys package local.modem.sms | busybox grep userId=
am force-stop local.modem.sms
# Сохраните прежний каталог; выберите свободное имя вместо <метка>.
mv /data/data/local.modem.sms /data/local/sms-only/app-before-restore-<метка>
busybox tar -xpf /data/local/tmp/sms-restore.tar -C /data/data
# Подставьте фактический userId из dumpsys package, не UID другого модема.
chown -R <uid>:<uid> /data/data/local.modem.sms
restorecon -R /data/data/local.modem.sms
am startservice -n local.modem.sms/.SmsService
exit
```

Убедитесь, что `restorecon` доступен и завершился без ошибки; при другой SELinux-конфигурации сначала восстановите корректную метку данных приложения. Архив нужно развернуть вместо прежнего каталога, чтобы старые SQLite journals не смешались с восстановленными. Затем на компьютере верните обычный ADB и проверьте страницу:

```powershell
Set-ModemRoot $adb $serial $false
.\scripts\Verify-Modem.ps1 -Serial $serial -Adb $adb
```

Удалите временный архив на модеме и прежний каталог только после подтверждения восстановления и наличия другой закрытой копии. Восстановление собственного inbox.db возвращает и записи `deleted_messages`, определяющие, какие сообщения нельзя повторно импортировать.

## Откат сетевой политики

Предпочтительный откат — возврат последней рабочей SMS-only конфигурации из конкретного снимка, а не восстановление заводского роутера. Резервная копия может содержать старый USB-обработчик с ошибкой PID или включённые таймеры перезагрузки. Сверьте её содержание перед восстановлением.

Через временный root ADB сохраните нынешние файлы отдельно. В `/data/local/sms-only/backups/<epoch>-<pid>/system/` лежат исходные четыре файла или `*.absent`. Верните сохранённые файлы в `/system/etc/` с владельцем `0:0` и исходными правами; для файлов с отметкой `absent` удаляется только соответствующий добавленный файл. Обязательно верните сохранённый `init.qcom.post_boot.sh`, иначе в нём останется ссылка на удалённую политику. Используйте `mount -o remount,rw /system` только на время копирования и завершите `mount -o remount,ro /system`.

После восстановления файлов нужна контролируемая перезагрузка: запущенный USB-обработчик продолжает использовать функции, загруженные в память до отката. Если требуется снять только свои цепочки firewall немедленно, сначала остановите именно этот обработчик, проверив PID-файл, boot_id и `/proc/<pid>/cmdline`. Затем в Android shell:

```sh
for fw in iptables ip6tables; do
    for pair in INPUT:SMS_ONLY_IN OUTPUT:SMS_ONLY_OUT FORWARD:SMS_ONLY_FWD; do
        parent=${pair%%:*}
        chain=${pair#*:}
        while "$fw" -C "$parent" -j "$chain" 2>/dev/null; do
            "$fw" -D "$parent" -j "$chain"
        done
        "$fw" -F "$chain" 2>/dev/null
        "$fw" -X "$chain" 2>/dev/null
    done
done
```

Это удаляет только собственные цепочки проекта. Нельзя выполнять общий `iptables -F` или обнулять правила производителя.

Исходные global settings и `persist.ufi.nosignal.reboot` находятся в `state/`. Значение `null` означает отсутствие setting и восстанавливается через `settings delete global <имя>`, остальные — через `settings put global <имя> <значение>`. Прежний `vendor-config.xml` возвращается только с владельцем `1000:1000`, правами каталога `700`, файла `600` и корректной SELinux-меткой; отметка `absent` означает, что раньше файла не было.

Не возвращайте `persist.ufi.nosignal.reboot=yes` или `testConnect=true`, сохраняя мобильные данные выключенными: это воспроизводит найденную петлю перезагрузок. `pm enable` для MoSdk, StickService или Elink выполняется только при осознанном возврате их функций; одновременно следует пересмотреть сетевую политику и таймеры. Для штатной эксплуатации SMS-only такой возврат не нужен. Whole-package SystemUI/phone/RIL отключать нельзя.

Чтобы вернуть заводской роутер с Wi-Fi и интернетом, потребуется отдельная конфигурация tethering, Wi-Fi helper, firewall, адресов и панели. Один `svc data enable` не отменяет SMS-only режим. Этот репозиторий устанавливает и поддерживает целевой режим приёмника СМС.
