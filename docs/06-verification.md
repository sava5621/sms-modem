# Проверка приёма СМС и стабильности

## Перезагрузка и базовое состояние

Перезагружайте после завершения установки и возврата ADB к `uid=2000`. Во время проверки не трогайте модем, USB-порт и SIM: физическое отключение должно учитываться отдельно от программного сбоя.

```powershell
& $adb -s $serial reboot
# Подождите появления устройства в adb devices и страницы HTTP.
.\scripts\Verify-Modem.ps1 -Serial $serial -Adb $adb
```

После загрузки дайте около 40–60 секунд на инициализацию. `sys.boot_completed=1` может появиться раньше готовности USB-сети. При необходимости проверьте `adb devices -l` и повторите проверку после появления HTTP. Скрипт не перезагружает модем сам.

Ожидаются SIM `READY`, HTTP `200`, mobile_data/roaming/Wi-Fi/scan/tether_supported и IPv4/IPv6 forwarding равные `0`, USB tethering `false`, reboot watchdog `no`, ADB UID `2000`, `/system` read-only. Для Wi-Fi ожидается `ApStaDisabledState`, процессы `hostapd`, `wpa_supplicant`, `dnsmasq` отсутствуют; MoSdk отключён. Без вставленной исправной SIM результат `ABSENT` закономерен, но реальный приём проверить нельзя.

Скрипт читает API только для числа сообщений и не выводит номера или тексты. Чтобы сохранить собственный отчёт, предварительно создайте `.local/` и задайте `-OutputFile .\.local\verification.json`.

## Firewall и службы

Проверьте сетевой доступ с компьютера: TCP 8088 доступен, TCP 8000, 10242 и 53 недоступны. `Test-NetConnection 192.168.100.1 -Port 8088` проверяет доступность HTTP-порта. Закрытый TCP 53 сам по себе не проверяет UDP DNS; запрет обеих разновидностей следует из правил firewall.

Из временной root-сессии отдельно посмотрите обе семьи правил:

```powershell
Import-Module .\scripts\Modem.psm1 -Force
Set-ModemRoot $adb $serial $true
try {
    foreach ($cmd in @('iptables -S','ip6tables -S','iptables -nvL SMS_ONLY_OUT',
        'ip addr','dumpsys connectivity','dumpsys package com.wowi.nanowebyl',
        'dumpsys package com.android.systemui')) {
        Invoke-ModemShell $adb $serial $cmd
    }
} finally {
    Set-ModemRoot $adb $serial $false
}
```

Нужны первые переходы к `SMS_ONLY_*`, итоговые DROP в собственных цепочках, отсутствие forwarding и активного tethering. В `disabledComponents` должны находиться только указанные на [этапе 5](05-sms-only.md) компоненты панели и Elink; весь SystemUI должен оставаться включённым. На устройстве может быть LISTEN 10242, доступ извне к нему должен блокироваться. Сами таблицы и состояние важнее отсутствия одного процесса.

Если требуется проверка исходящих запросов, счётчики `SMS_ONLY_OUT` позволяют увидеть блокировки. Для пассивного захвата на компьютере выбирайте только USB-интерфейс и сохраняйте адреса/порты без содержимого СМС. Проверка до изменения политики обнаружила код внешних запросов в прошивке; итоговый 90-секундный захват не показал внешнего IPv4-трафика модема. Короткий захват не является доказательством поведения за любой период.

## Реальное тестовое сообщение

1. Откройте `http://192.168.100.1:8088/`, запомните число СМС.
2. Отправьте с другого телефона новое сообщение с уникальным текстом на номер SIM модема.
3. Дождитесь обновления страницы (обычно она опрашивает сервис раз в 10 секунд), проверьте отправителя и полный текст, в том числе кириллицу.
4. Повторите проверку mobile_data=`0` и forwarding=`0` в момент приёма.
5. Обновите страницу и перезапустите только SMS-службу или выполните плановую перезагрузку. Сообщение должно остаться в архиве.

В [испытании 17.10.2026](../reports/2026-10-17/README.md) реальное сообщение получено: число записей увеличилось с 47 до 48 при выключенных данных. Отправитель и содержимое не сохранены в отчёте.

## Наблюдение после пяти минут

```powershell
.\scripts\Measure-Stability.ps1 -Serial $serial -Adb $adb -Minutes 10 -IntervalSeconds 20
```

Сценарий только наблюдает: HTTP, `boot_id`, uptime, SIM, mobile_data, forwarding, выключатель перезагрузки и raw температуру thermal_zone0. Он ничего не перезапускает. CSV и итоговый JSON пишутся в исключённый из Git каталог `.local/measurements/`; тела СМС не считываются. Температура сохраняется как сырое значение, её единицы нужно сверять с конкретным thermal driver.

Успех короткого испытания — HTTP доступен на каждом замере, один `boot_id`, uptime растёт, SIM READY, данные и forwarding выключены, watchdog `no`. Новый `boot_id` означает загрузку ОС; пропавший USB при прежнем boot_id может означать сброс USB-порта или adbd. Для сервера затем проведите наблюдение в его реальных условиях, с тем же питанием и USB-портом. Проверка в несколько минут не подтверждает месяцы бесперебойной работы.
