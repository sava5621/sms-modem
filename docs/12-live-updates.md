# Живое обновление СМС и состояние сети

Версия 4.0 добавляет стандартный WebSocket на том же TCP 8088, автоматическое обновление списка при поступлении и удалении СМС, а также состояние SIM и сигнал оператора. Кнопка «Обновить» сохранена. Включать мобильные данные, Wi-Fi или раздачу для этих функций не требуется.

## Обновление с версии 3

Сохраните закрытую резервную копию по [этапу 3](03-backup.md), если копирование сообщений разрешено владельцем. Обновление через `adb install -r` сохраняет данные; схема SQLite остаётся version 2, ключ подписи готового APK тот же. Новый файл — `artifacts/sms-modem-4.0.apk`.

```powershell
.\scripts\Install-Apps.ps1 -Serial $serial -Adb $adb
```

Этот сценарий также проверяет checksum поставки и наличие Wi-Fi helper. Он не перепрошивает устройство и не меняет SMS-only политику. Откройте страницу заново, чтобы загрузился новый HTML. В manifest добавлено `READ_PHONE_STATE` для чтения состояния телефонии на Android 4.4; номера телефона, IMEI, IMSI и ICCID сервис не публикует.

## Поведение интерфейса

Соединение открывается на `/ws` с `ws://` для локального HTTP или `wss://` для HTTPS proxy. После `ready` страница загружает актуальный список; `messages` вызывает повторное чтение текущего списка через HTTP API. Пакеты событий не содержат тела или отправителя сообщения. Сохраняются текущая вкладка, фильтр отправителя и число загруженных записей.

Если пользователь выбирает сообщения для удаления, обновление списка откладывается и появляется уведомление об изменениях. Выбор остаётся на месте. После завершения выбора загружается актуальный список. Событие, пришедшее во время HTTP-запроса, ставит дополнительное обновление в очередь, чтобы не потеряться.

При обрыве выполняется переподключение с задержкой 1, 2, 4, … до 30 секунд. Пока постоянное соединение недоступно, список и состояние сети запрашиваются каждые 10 секунд; ручная кнопка действует независимо от WebSocket. При возвращении на вкладку данные сверяются заново. Скрытая вкладка освобождает соединение.

## SIM и уровень сигнала

Карточка SIM различает READY, ABSENT, PIN_REQUIRED, PUK_REQUIRED, NETWORK_LOCKED, NOT_READY и неизвестное состояние. Карточка сети показывает регистрацию у оператора, название оператора, технологию сети и 0–4 деления сигнала. Для LTE выводится RSRP в дБм; для GSM/CDMA — доступная оценка RSSI. Деления описывают радиосигнал и не являются оценкой скорости интернета или гарантией доставки СМС.

`PhoneStateListener` наблюдает service state и signal strength; дополнительно обрабатываются события SIM/авиарежима и раз в 10 секунд локально сверяется состояние. Это обращения к Android telephony API внутри модема, без внешних сетевых запросов и без включения data connection.

При отсутствии SIM/регистрации старое значение сигнала очищается. Неизвестные значения, в том числе Android sentinel `2147483647` и GSM ASU `99`, не превращаются в фиктивные дБм/полные деления. В KitKat `getLteRsrp` и `getLevel` скрыты из публичного SDK, поэтому используются через reflection с проверкой диапазонов и запасным расчётом уровня по доступному измерению. Источник структуры сигнала — [AOSP Android 4.4.4 SignalStrength](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-4.4.4_r2/telephony/java/android/telephony/SignalStrength.java).

## HTTP API состояния

`GET /api/status` возвращает состояние без содержимого СМС. Пример с вымышленными значениями:

```json
{
  "type": "status",
  "revision": 12,
  "network": {
    "simState": "READY",
    "simPresent": true,
    "simReady": true,
    "registered": true,
    "serviceState": "IN_SERVICE",
    "operator": "Test Mobile",
    "technology": "LTE",
    "signalLevel": 3,
    "signalDbm": -101,
    "signalMetric": "RSRP",
    "available": true,
    "updatedAt": 1700000000000
  }
}
```

`simPresent` может быть `null`, если карта не определена; `signalDbm` и `signalLevel` — `null`, если измерение неизвестно или нет регистрации. `revision` — счётчик изменений собственного архива за время жизни процесса службы. После перезапуска он сбрасывается, поэтому клиент всегда сверяет список после нового `ready`.

## WebSocket API

Handshake соответствует [RFC 6455](https://datatracker.ietf.org/doc/html/rfc6455): HTTP/1.1 GET `/ws`, `Upgrade: websocket`, Connection с токеном Upgrade, версия 13 и корректный 16-байтовый `Sec-WebSocket-Key`. Требуется разрешённый Origin и существующая проверка Host; отсутствие Origin или посторонний сайт даёт `403`, неверная версия — `426`.

Сервер отправляет JSON text frames: `ready` с network/revision при подключении, `messages` с новой revision при реальном добавлении/удалении, `network` с изменившимся снимком и `heartbeat` примерно раз в 20 секунд. Дубликат СМС, отклонённый SQLite, не увеличивает revision. События нескольких записей объединяются с задержкой 100 мс. Команды чтения/удаления через WebSocket не принимаются; удаление остаётся в прежнем защищённом HTTP API.

До 8 одновременных соединений обслуживаются отдельно от пула HTTP. У каждого ограничена очередь из 32 кадров; медленный клиент отключается при переполнении. Есть native ping/pong, таймаут чтения 45 секунд, проверка masking/control frames, закрытие при некорректном протоколе и освобождение сокетов при остановке службы. При превышении лимита возвращается `503`, обычный HTTP остаётся доступен.

## Reverse proxy

Для локального адреса дополнительная настройка firewall не нужна: используется прежний порт 8088. Для внешнего HTTPS proxy нужно передавать HTTP/1.1 Upgrade. Пример части уже существующего nginx server для разрешённого Host:

```nginx
location /ws {
    proxy_pass http://192.168.100.1:8088;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header Origin $http_origin;
    proxy_read_timeout 75s;
    proxy_buffering off;
}
```

Proxy должен иметь локальную достижимость USB-адреса и собственную авторизацию для просмотра СМС. При использовании внешней авторизации она должна применяться и к `/ws`, и к HTTP API. Сценарии проекта не разворачивают публичный proxy; если Upgrade не настроен, ручное и резервное HTTP-обновление сохраняются.
