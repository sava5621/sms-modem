# Устройство SMS сервиса и HTTP API

## Приём и хранение

Android receiver принимает `android.provider.Telephony.SMS_RECEIVED`, объединяет multipart-части одного broadcast и сохраняет сообщение в собственную SQLite. `BootReceiver` запускает службу после загрузки и замены пакета; служба использует `START_STICKY`. При старте выполняется импорт системного `content://sms/inbox`.

SQLite `/data/data/local.modem.sms/databases/inbox.db` имеет schema version 2. `messages` содержит `_id`, `message_key`, `sender`, `body`, `sent_at`, `received_at`, `source`; `deleted_messages` хранит отпечатки удалённых записей. SHA-256 от отправителя, отправленного времени и текста подавляет повторный импорт. Архив приложения находится во внутренней памяти Android, а не является прямым просмотром SIM storage.

Удаление убирает выбранные записи только из архива приложения, оставляя tombstones для предотвращения повторного импорта. Системный inbox и SIM этим действием не очищаются. Отправка СМС через UI/API не предусмотрена. Произвольные HTML-теги из текста сообщения отображаются как текст.

## HTTP и интерфейс

Служба привязана к `192.168.100.1:8088`, повторяет bind раз в 3 секунды до появления адреса. Допускаются peer из `192.168.100.*` и loopback. Используются ограниченный пул обработчиков, таймауты сокета, `Cache-Control: no-store` и защитные HTTP headers.

UI показывает все СМС или группы по отправителю, позволяет загрузить следующую страницу и обновляется по событиям WebSocket. При недоступном соединении используется резервный опрос раз в 10 секунд; кнопка «Обновить» действует вручную. Выбор сообщений откладывает обновление списка, сохраняя выделение. Карточки SIM и сети показывают состояние карты, регистрацию и сигнал. Нет внешних JS/CSS библиотек или CDN. Протокол и статус описаны в [отдельном файле](12-live-updates.md).

Просмотр не требует пароля: любой клиент с разрешённым сетевым доступом может читать архив. Локальная схема предполагает выделенное USB-соединение. В исходной версии сохранён Host allowlist прежнего reverse proxy `sms-manager.nightlife-server.ru` с HTTPS Origin. Приложение не подключается к этому домену само; в SMS-only режиме новые исходящие соединения модема запрещены. Публичный proxy, его TLS и авторизация не разворачиваются сценариями проекта. При переносе на другой публичный домен нужен пересмотр `PUBLIC_HOST` и отдельная защита доступа на proxy.

## Чтение

| Метод и путь | Результат |
| --- | --- |
| `GET /` или `/index.html` | Локальная HTML-страница |
| `GET /api/sms` | JSON с messages, total, globalTotal, hasMore, providerAvailable, updatedAt |
| `GET /api/sms?sender=...&offset=0&limit=100` | Точный фильтр отправителя, пагинация |
| `GET /api/senders?offset=0&limit=100` | Группы отправителей, счётчики и превью |
| `GET /api/status` | Состояние SIM/регистрации/сигнала и revision архива, без СМС |
| `GET /ws` с Upgrade | Постоянное соединение с событиями изменений |

Для чтения допускается `HEAD`. `offset` ограничен 0…1 000 000, `limit` — 1…200 (по умолчанию 100). Сортировка сообщений — `_id DESC`, поэтому это порядок добавления в архив. Отправитель кодируется как URL query value. `sentAt` и `receivedAt` — Unix time в миллисекундах. Пример с вымышленными данными:

```json
{
  "messages": [{"id": 1, "sender": "TEST", "body": "Проверка", "sentAt": 1700000000000, "receivedAt": 1700000000000}],
  "total": 1,
  "globalTotal": 1,
  "hasMore": false,
  "providerAvailable": true,
  "updatedAt": 1700000000000
}
```

`providerAvailable=false` означает ошибку последнего импорта системного inbox; собственная база может продолжать содержать сообщения. Это не показатель регистрации SIM.

## Удаление

`POST /api/sms/delete` принимает JSON размером 1…16384 байта с `Content-Type: application/json`, заголовком `X-SMS-Action: delete` и телом вида `{"code":"3412","ids":[1,2]}`. Это пример формата, не команда для запуска на настоящих сообщениях. Допускается 1…500 положительных целых ID, повторяющиеся ID объединяются. Ответ успешного удаления — `{"deleted":2}`.

Код рабочей версии — `3412`. Сервер сравнивает SHA-256 с константой `EXPECTED` в `DeleteGuard.java`, в HTML кода нет. Это известное проектное значение, которое следует изменить перед предоставлением интерфейса другим пользователям; оно не защищает чтение архива. Смена требует пересчёта SHA-256 и сборки с тем же ключом подписи. После пяти неправильных попыток для peer действует блокировка на 60 секунд.

Ошибки: `403 wrong_code`, `429 try_later` с `retryAfter`, `400` при неверных ID/JSON/размере, `415` при неверном формате. Проверяются Host и Origin; локальный Origin должен соответствовать локальному HTTP Host, для разрешённого публичного Host требуется HTTPS Origin. Неподдерживаемые маршруты возвращают `404`, методы — `405`.
