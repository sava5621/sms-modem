# Включение режима только СМС

Этап меняет системные настройки проверенной прошивки. Приложения должны быть установлены по [этапу 4](04-network-and-apps.md), резервные копии подготовлены по [этапу 3](03-backup.md). Доступ по USB ADB нужен независимо от состояния IP-сети.

## Установка

```powershell
.\scripts\Install-SmsOnly.ps1 -Serial $serial -Adb $adb
```

Скрипт проверяет fingerprint и SHA-256 файлов, загружает три файла политики и установщик в `/data/local/tmp/sms-only-install/`, временно включает root ADB, выполняет установщик и возвращает ADB к `uid=2000`. Он не перезагружает устройство автоматически. При ошибке сначала прочитайте сообщение и проверьте возврат обычных прав, а затем используйте [диагностику](07-troubleshooting.md).

Успех обозначается строкой `SMS_ONLY_INSTALLED backup=/data/local/sms-only/backups/...`. Сохраните указанный каталог. На уже настроенном модеме повторная установка создаёт новый снимок, а не затирает предыдущий.

## Что меняется

| Настройка | Целевое состояние |
| --- | --- |
| `settings global mobile_data` | `0`, также `svc data disable` |
| `data_roaming` | `0` |
| `wifi_scan_always_enabled` | `0` |
| `tether_supported` | `0` |
| `wifi_on` | `0`; Wi-Fi client и AP выключаются через системные API |
| `sys.usb.tethering` | `false` |
| IPv4/IPv6 forwarding | `0` |
| `persist.ufi.nosignal.reboot` | `no` |
| Панель `config.xml`, `testConnect` | `false` |

Выключены конкретные ненужные компоненты:

| Цель `pm disable` | Назначение |
| --- | --- |
| `com.mo.sdk2230` | Отдельный предустановленный SDK с SMS/network-разрешениями и загрузкой дополнительного кода |
| `com.wowi.nanowebyl/com.wowi.nanoweb.StickService` | Штатный HTTP-сервер 8000 и связанная логика панели |
| `com.android.systemui/com.android.systemui.ElinkAutoTestService` | Смешанная автодиагностика с облачными запросами и командами перезагрузки |

Пакеты `com.android.systemui` и `com.wowi.nanowebyl` целиком остаются включены. Службы телефонии, RIL/QCRIL, SIM, `netd`, управление питанием и температурой сохраняются. `com.android.exchange` был отключён на этом экземпляре раньше из-за отсутствующего почтового провайдера; новый установщик его не меняет.

Установка не меняет драйвер Wi-Fi: прошивка может попытаться включить AP раньше срабатывания Android-обработчиков. В проверенном установившемся состоянии Wi-Fi/AP выключены; полное отсутствие краткого радиоизлучения с момента подачи питания отдельно не измерялось.

Штатная панель на 80/8000 после этого недоступна. Рабочий интерфейс — TCP 8088. Код внешних запросов в предустановленных APK стал основанием отключить ненужные компоненты; это не доказательство передачи СМС во время наблюдения.

## Защита от перезагрузки без интернета

В этой прошивке `NetworkController$3` внутри SystemUI при SIM READY и отсутствии data connection мог отправлять `ACTION_REBOOT` примерно через 5 минут. Значение `persist.ufi.nosignal.reboot=no` предусмотрено самим кодом как выключатель этой проверки. Оно позволяет оставить сотовую регистрацию и приём СМС включёнными.

У штатной панели есть другой таймер `testConnect`, по умолчанию включённый. Он способен запросить перезагрузку после 300 секунд без интернета при действующей SIM. Установщик выключает и его. Отключение только мобильных данных без этих изменений оставляло конфликт с назначением устройства.

## Системные файлы и автозапуск

Устанавливаются:

- `/system/etc/modem-usb-lan.sh` — восстанавливает `rndis0 = 192.168.100.1/24`, запускает политику и проверяет USB-сеть каждые 5 секунд;
- `/system/etc/sms-only-policy.sh` — настройки, firewall, контроль каждые 30 секунд и журнал здоровья каждые 5 минут;
- `/system/etc/sms-only-control.jar` — одноразовый root-вызов Android API для отключения tethering/Wi-Fi/AP и записи `testConnect=false`.

В существующий `/system/etc/init.qcom.post_boot.sh` добавляется вызов USB-обработчика через `busybox setsid`, если его ещё нет. Штатный сценарий целиком не заменяется. Установщик завершится ошибкой, если для нового hook обнаружен явный `exit`, требующий ручной проверки места вставки. `/system` возвращается в read-only через trap даже при ошибке.

PID-файл обработчика хранит PID вместе с `boot_id`; проверка процесса исключает ошибку устаревшего PID после перезагрузки. Сам обработчик перезагрузок не вызывает.

## Сетевая политика

Собственные цепочки `SMS_ONLY_IN`, `SMS_ONLY_OUT`, `SMS_ONLY_FWD` подключаются первыми к INPUT, OUTPUT и FORWARD для IPv4 и IPv6. IPv4 допускает вход TCP 8088 от `192.168.100.0/24` к `192.168.100.1`, ICMP echo-request из LAN, loopback и установленные соединения. Исходящий IPv4 разрешает loopback и ответы установленных соединений в USB-подсеть. Новые исходящие соединения и forwarding запрещены. Для IPv6 внешнего исходящего доступа и forwarding также нет.

ADBD этой прошивки может продолжать слушать TCP 10242 внутри устройства, но firewall блокирует доступ к этому порту из сети. USB ADB не использует IP и сохраняется. Запрет IP-трафика не означает выключение служебного радиообмена с оператором, необходимого для регистрации и СМС.

При `tether_supported=0` Android API `setUsbTethering(false)` может вернуть `3` («не поддерживается»); этот результат сам по себе не означает включённую раздачу. Проверяется фактическое состояние tethering, forwarding и процессов. Файлы предпочтений панели после root-вызова возвращаются владельцу `1000:1000`.
